# scripts

- `test/fixtures/*.json` were generated once from the retired browser engine (`author/codex.js`) at commit 4682996. To regenerate, check out that commit's `scripts/gen-fixtures.mjs`, `author/` and `site/author/data.json` and run it; the ported engine must reproduce every file.
- `migrate-ledger.mjs` — the one-time split of the chapter files into `volumes/mwr/**`. Kept for the record; it is not needed again.
- `handoff.ts` — writes `handoff/<volume>.md` from the checked-in ledger, for every volume (or `--volume <id>`). Run `npm run handoff`.
- `conformance.ts`, `conform.ts`, `export.ts`, `check.ts`, `governance-report.ts`, `fingerprint.ts` — the conformance suite, the harness, the JSON export, the check, the governance report and the approval fingerprint (docs/governance.md "Stale approvals"); each runs every volume unless given `--volume <id>`. See `docs/conformance.md`.
- `codex_tool.py` — the original Python reference checker. Not used at runtime. `python3 scripts/codex_tool.py --help` (needs PyYAML) if you ever want a second opinion on the ledger.
- `receipts/` — receipt records (CO-5000; docs/reviews/receipts-migration-1.md). `npm run receipts:harness` runs the metamorphic relations and families (`metamorphic.ts`) over every stored household and the generated households (`generate.ts`: each base varied one receipt at a time, stated in receipts alone). Its report is `receipts/results/harness.txt`. `ledgers.ts` loads the ledger on disk, or at a ref for `audit/answer-diff.ts`.
- `records/` — earnings and holdings records (CO-5100, CO-5300; docs/design-earned-and-resource-records.md). `npm run records:harness -- --list earnings` runs the boundary lint with receipts (`boundary.ts`) and the metamorphic relations ME-1 to ME-4; `--list holdings` the joint-holding lint and the relations MH-1 to MH-5; each over the stored households, the rule tests (for the lints) and the generated households of each track's bases (`generate-*.ts`, `programs/*.ts`). Reports in `records/results/`. Known pairs and joint findings are dispositioned in `records/allowed/boundary.yaml` and `joint.yaml`.
- Until steps E2 and H2 (2026-11-24, docs/reviews/records-e2-h2.md) both directories also held the translators from the scalar income and resource facts, `npm run receipts:translate`, `records:translate` and `records:translate-holdings`, the retired statements (`receipts/retired-facts.yaml`) and the old-against-new comparison with its allowed-difference files. The scalar facts are retired and every household states records alone, so those are gone.
