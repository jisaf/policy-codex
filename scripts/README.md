# scripts

- `test/fixtures/*.json` were generated once from the retired browser engine (`author/codex.js`) at commit 4682996. To regenerate, check out that commit's `scripts/gen-fixtures.mjs`, `author/` and `site/author/data.json` and run it; the ported engine must reproduce every file.
- `migrate-ledger.mjs` — the one-time split of the chapter files into `volumes/mwr/**`. Kept for the record; it is not needed again.
- `handoff.ts` — writes `handoff/<volume>.md` from the checked-in ledger, for every volume (or `--volume <id>`). Run `npm run handoff`.
- `conformance.ts`, `conform.ts`, `export.ts`, `check.ts`, `governance-report.ts`, `fingerprint.ts` — the conformance suite, the harness, the JSON export, the check, the governance report and the approval fingerprint (docs/governance.md "Stale approvals"); each runs every volume unless given `--volume <id>`. See `docs/conformance.md`.
- `codex_tool.py` — the original Python reference checker. Not used at runtime. `python3 scripts/codex_tool.py --help` (needs PyYAML) if you ever want a second opinion on the ledger.
- `receipts/` — receipt records, migration phase 1 (docs/reviews/receipts-migration-1.md). `translate.ts` restates the scalar unearned-income facts as the `receipts` list (CO-5000); `npm run receipts:translate` writes it into every stored household and rule test that states them, keeping the old facts for the programs not yet migrated (the transition rule). `npm run receipts:harness` is the merge gate: every stored and generated household (`generate.ts`) on the ledger before the migration and on the ledger on disk, every difference matched against `allowed-differences.yaml` or failing, every stored household's receipts checked to be the translation of its old facts, and the metamorphic relations and families (`metamorphic.ts`). Its report is `receipts/results/harness.txt`.
