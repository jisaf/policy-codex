# Resuming the Colorado build in a fresh session

1. Confirm network access first: `curl -sS -o /dev/null -w '%{http_code}\n' https://www.ecfr.gov/api/versioner/v1/titles.json` must print 200 (and likewise sos.state.co.us, law.cornell.edu, hcpf.colorado.gov). If any print 000 or 403, stop and report; authoring must not proceed from memory. Cornell's CCR mirror (law.cornell.edu/regulations/colorado/...) worked in every session so far; hcpf.colorado.gov, cdhs.colorado.gov, usda.gov, medicaid.gov and ssa.gov did not.
2. Read, in order: docs/design-colorado.md, docs/plan-colorado.md, docs/colorado-notes.md, docs/governance.md, docs/conventions.md, volumes/co/volume.yaml, volumes/co/tests/cases.yaml, and the reviews in docs/reviews/.
3. Phases 2–6 (SNAP; MAGI Medicaid and CHP+; non-MAGI Medicaid, LTC, MSP and Buy-In; Colorado Works and Adult Financial; CCCAP and LEAP) are built and reviewed on the branch of PR #8. What remains is in volumes/co/open-questions.md: state-published figures to replace supplied facts with parameters once fetched (the HCPF income chart, the CHP+ fee schedule, the CSRA/MMMNA/home-equity/transfer-divisor standards, the OAP and AND grant standards, the LEAP income ceiling and benefit matrix, county CCCAP entry limits), rule sections not yet fetched (9 CCR 2503-6 3.608 sanctions), and modeling gaps that need a co-residence fact or a volume-declared relationship role.
4. Mechanics for any further batch: fetch documents into `volumes/co/documents/D-n.md` (D-1..D-64 exist; `documents.yaml` lists them), append excerpts to `volumes/co/sources.md` with `Document: D-n` lines, author items with `rationale` on every new item and rule tests, then `node scripts/sync-manifest.mjs co`, `npm run governance -- --volume co`, `git add` the new files, and `CHECK_BASE=origin/main npm run check` over all volumes, as CI runs it (the `--volume co` form skipped type errors that CI then caught; a file counts as new only once git tracks it). `npx vite-node scripts/eval-case.ts co CO-01 <identifiers>` shows a case's values and the supplied facts still missing.
5. Use subagents: one author per chapter batch (sonnet), one policy reviewer per program (opus, reviewing against the fetched text — every phase's review found blocking defects that governance and check passed), fix rounds split in two when the list is long, and a case designed by the reviewer added after the fixes. No more than three concurrent agents; each stages only its own files and the coordinator validates and commits from the combined tree.
