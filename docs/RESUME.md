# Resuming the Colorado build in a fresh session

1. Confirm network access first: `curl -sS -o /dev/null -w '%{http_code}\n' https://www.ecfr.gov/api/versioner/v1/titles.json` must print 200 (and likewise sos.state.co.us, law.cornell.edu, hcpf.colorado.gov). If any print 000 or 403, stop and report; authoring must not proceed from memory.
2. Read, in order: docs/design-colorado.md, docs/plan-colorado.md, docs/colorado-notes.md, docs/governance.md, docs/conventions.md, volumes/co/volume.yaml, volumes/co/tests/cases.yaml.
3. Phase 2 (SNAP) is done (docs/colorado-notes.md, docs/reviews/snap-phase-2.md). Phase 3 (MAGI Medicaid and CHP+) starts by fetching the documents named in the plan into `volumes/co/documents/D-n.md` (D-1..D-25 exist; continue the numbering; `documents.yaml` lists them) and appending excerpts to `volumes/co/sources.md` with `Document: D-n` lines (S1..S135+ used), then authoring in batches of about 30 items under `volumes/co/medicaid` and `volumes/co/chp` (shared facts under `supplied`/`parameters`; ids CO-500.. for Medicaid rules, CO-700.. for CHP+, parameters CO-180.., supplied CO-075..), each with `rationale` on every new item (supplied facts and parameters included) and rule tests, running `node scripts/sync-manifest.mjs co`, `npm run governance -- --volume co` and `git add` then `CHECK_BASE=origin/main npm run check -- --volume co` after each batch (check counts a file as new only once git tracks it). `npx vite-node scripts/eval-case.ts co CO-01 <identifiers>` shows a case's values and the supplied facts still missing. Note from phase 2: hcpf.colorado.gov and cdhs.colorado.gov returned 403 to this session while Cornell's mirror of the CCR (law.cornell.edu/regulations/colorado/...) worked; 10 CCR 2505-10 8.100 is at 10-CCR-2505-10-8.100 there.
4. Use subagents: one author per chapter batch (sonnet), one policy reviewer per program (opus) reviewing against the fetched text, and haiku for transcription-only work. Pace dispatches to avoid rate limits: no more than three concurrent authors.
5. Every phase ends with the target household's expectations for that program filled in `volumes/co/tests/cases.yaml`, a policy review, a fix round, a phase note in docs/colorado-notes.md, and a pull request into main.
