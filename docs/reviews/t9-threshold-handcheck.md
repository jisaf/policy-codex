# T-9 threshold tests: hand check against the rule text

Independent review of the 129 rule tests titled "T-9: ..." that the time-audit fix round added (`grep -rn '"title": "T-9' volumes/co`, 77 items). Reviewed at ccbb3a7 (branch ccr-9d19bf4c-wmnwcl), 2026-11-23, in a scratch copy. Read-only: no item or test was changed.

Each T-9 test evaluates one threshold comparison with both sides equal. Its expected value was generated by the evaluator, so it records what the codex does at the boundary. The product owner's rule is that a test asserts the rule's answer. For every test this review read the item's cited excerpts in `volumes/co/sources.md`, decided from the wording which side the equal case falls on, and compared that with the expected value. Where the cited excerpts were silent, the rest of `sources.md`, `open-questions.md` and the item's `statute_override` and `precision` were checked.

No test asserts an answer that the text clearly contradicts. Twelve tests lock in a boundary reading that the text does not settle and that no open question records. Several of those twelve are internal inconsistencies, where the codex reads the same kind of wording one way in one item and the other way in another (A-3/A-4, A-8, A-6/A-7).

### Mechanical checks (all 129)

- **Sides equal.** For each test, both sides named in the title were evaluated under the test's own `given`, `month` and `as_of` with the reference evaluator, using `runTest` on a throwaway item. All 129 are equal. The nine numeric-literal sides (`0`, `1`) differ only as the string "0" against the number 0, which comes from parsing the title.
- **Comparison is decisive.** Every comparison node whose operands match the title was flipped between strict and inclusive (`<`/`<=`, `>`/`>=`) across the ledger, and the test was re-run. All 129 tests fail on their flipped mutant, so each one decides its boundary.
- **Consistency of the givens (P2).** Most tests reach the boundary by stating a derived value directly, which overrides its rule. In 33 tests that stated value contradicts other facts in the same `given`. None of these breaks the boundary test, but a reader can be misled by them, and the test would no longer test the boundary if the stated value were ever removed. They are listed under "Givens that contradict themselves" below.

## Method and reproduction

A scratch copy at ccbb3a7 was used (`git archive` with `node_modules` linked). The two mechanical checks are short vite-node scripts that use `loadLedgerFromDisk`, `buildIndex` and `runTest` from the repository, unchanged:

1. Each title is parsed as "X equal to Y (...)". X and Y are evaluated as throwaway derived items under the test's `given`, `month` and `as_of`, and compared.
2. Each `<`/`<=`/`>`/`>=` node whose operands match X and Y is flipped strict/inclusive across every item. The test is re-run against the mutated ledger, and the check expects it to fail.

The consistency list comes from re-evaluating each stated derived fact with its own override removed. The wording verdicts are by hand from `volumes/co/sources.md`. `npm run boundaries -- --only boundaries` was used only as a locator for wording, not for any verdict.
